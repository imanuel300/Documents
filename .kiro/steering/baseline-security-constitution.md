# חוקת אבטחת מידע בסיסית - Baseline Security Constitution

## מטרה
חוקה זו מגדירה את עקרונות אבטחת המידע המחייבים לכל מוצר דיגיטלי ממשלתי. כל קוד, מפרט, או תצורה שנוצרים על ידי סוכני AI חייבים לעמוד בכללים אלו.

## עקרונות מחייבים

### 1. הגנה על קלט המשתמש (Input Validation)
- כל שדה קלט חייב לעבור ולידציה בצד הלקוח (Client-Side Validation)
- שדות אימייל חייבים לעבור בדיקת פורמט תקני (RFC 5322)
- שדות טלפון חייבים לעבור בדיקת פורמט ישראלי (05X-XXXXXXX או 0X-XXXXXXX)
- אין לאפשר הזנת תווים מיוחדים מסוכנים (script tags, SQL injection patterns)
- יש ליישם sanitization על כל קלט חופשי (textarea) לפני עיבוד

### 2. הגנה מפני XSS (Cross-Site Scripting)
- כל תוכן שמוצג בדף חייב לעבור HTML encoding
- אין להשתמש ב-innerHTML עם תוכן שמגיע מהמשתמש
- יש להשתמש ב-textContent או ב-DOM API בטוח בלבד
- Content Security Policy (CSP) headers מומלצים

### 3. אבטחת מידע אישי (PII Protection)
- אין לאחסן מידע אישי ב-localStorage או sessionStorage ללא הצפנה
- אין להעביר מידע אישי ב-URL parameters
- יש לנקות טפסים לאחר שליחה מוצלחת
- אין לרשום מידע אישי ל-console בסביבת production

### 4. אבטחת תקשורת
- כל תקשורת חיצונית חייבת להתבצע באמצעות HTTPS בלבד
- אין לטעון משאבים חיצוניים מ-HTTP (mixed content)
- יש לוודא שימוש ב-Subresource Integrity (SRI) עבור ספריות צד שלישי

### 5. הגנה מפני CSRF
- כל טופס חייב לכלול token ייחודי (גם אם מדובר באב-טיפוס)
- אין לאפשר שליחה כפולה של טופס (double-submit prevention)

### 6. עקרונות Least Privilege
- אין לבקש הרשאות גישה שאינן נדרשות לתפקוד המערכת
- אין להריץ קוד עם הרשאות מוגברות ללא הצדקה

### 7. ניהול שגיאות מאובטח
- הודעות שגיאה לא יחשפו מידע טכני פנימי למשתמש הקצה
- יש לספק הודעות שגיאה ידידותיות בעברית
- שגיאות מערכת ירשמו ב-log פנימי בלבד

## הערות יישום
- חוקה זו חלה גם על אבות טיפוס (prototypes) - אין פשרה על אבטחה בשום שלב
- בסביבת מעבדה ללא Backend, יש ליישם את העקרונות הרלוונטיים בצד הלקוח בלבד
