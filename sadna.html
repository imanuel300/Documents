שלב 2: הגדרות בסיס ומושגי יסוד (SDD וחוקה)

הבנת תהליכי הפיתוח והתאמתם לפעילות סוכני ה-AI במעבדה

מתודולוגיית SDD

📄 1. מפרט כקוד (Spec as Code) וצמצום פער התיווך

מפרט כקוד (Spec as Code) הינו תהליך הפיתוח המתחיל ביצירת מפרט פורמלי ומדויק שעובר תיקוף על ידי AI. רק לאחר אישורו, סוכני ה-AI מתרגמים אותו לקוד באופן אוטונומי.

צמצום פער התיווך: ה-SDD מבטל את חוסר ההבנה בין דרישות המערכת לביצוע הטכני. אם הקוד אינו תואם ב-100% למפרט, הוא נדחה אוטומטית בשלב הבדיקות.

📜 2. חוקת הפרויקט (Constitution) ומתודולוגיית SDD

החוקה היא קבוצת עקרונות, כללים ואילוצים מחייבים המהווים את ה-DNA הארכיטקטוני של המערכת ושל פעילות סוכני ה-AI.

החוקה אינה מסמך תיעוד פסיבי, אלא שכבת דרישות אקטיבית שכל תוצר AI — מפרט, קוד, בדיקות, קונפיגורציה — מחויב לעמוד בה לאורך כל מחזור חיי המערכת. שיטת הפיתוח המשלבת חוקה ומפרט נקראת SDD — Spec-Driven Development (פיתוח מונחה מפרט).

💡 חיבור העקרונות למעבדה - בחירה בתצורת SPEC

בפלטפורמת Kiro קיימות שתי תצורות עבודה עיקריות: SPEC ו-VIBE. במעבדה זו אנו בוחרים באופן קשיח לעבוד בתצורת SPEC.

תצורת VIBE (קוד חופשי):

מתמקדת בפיתוח קוד חופשי ואינטואיטיבי (כמו כתיבה ידנית ישירה ושיחה שוטפת מול ה-AI), ללא שלבי אפיון ותיקוף קשיחים.

🎯 תצורת SPEC (תהליך מבוסס מפרט וחוקה):

המעבדה הזאת מתמקדת בתהליך עבודה של spec ביחד עם חוקה. הסוכן מחויב לאשר קודם את המפרטים ורק אז לגזור קוד התואם לחוקת הפרויקט.

חוקי עבודה ב-Kiro

לאחר שביצעתם את הגדרות הבסיס במעבדה, שימו לב לארבעה דגשים מרכזיים במהלך העבודה השוטפת שלכם מול סוכן ה-AI ב-Kiro:

1

שימוש בכפתור ה-Follow

⚠️ דגש חשוב: מה עושים כשהסוכן נראה "תקוע"?

במידה וזיהיתם שהסוכן נעצר, נראה תקוע, או שאינו מציג התקדמות והרצה בחלון העבודה, סביבת Kiro מבוססת על סוכן AI חכם שניתן לתקשר איתו ישירות בדיוק כמו שמדברים עם מפתח אנושי בצוות כדי להבין מה עוצר אותו.

ניתן לכתוב לו שאלות בדומה לשאלות ששואלים מפתח בצוות, למשל:

  • "למה הפסקת לעבוד?"
  • "מה הסיבה שאתה לא מריץ כלום?"
  • "האם נתקלת בקושי או שגיאה בבניית הקבצים?"

"המערכת תסווג את נושא הבקשה ותנתב אותה אוטומטית למשרד הממשלתי המתאים. המערכת תיבנה כ-single page application ב-core-web ללא Backend, ללא חיבור ל-database. המערכת תיבנה כאב טיפוס להמחשה בלבד, וכאשר האזרח שולח את הטופס הוא מקבל דף יחיד עם הודעת אישור."

"בסיום הכנת הפרויקט יש להקים סביבה להרצה: יש להפעיל שרת מקומי מתיקיית הפרויקט (למשל python3 -m http.server 8000) ולגשת ל-http://localhost:8000 ולספק למשתמש את הקישור להפעלה בדפדפן"

קראו את הדרישות שנוצרו ואשרו להתקדם לשלב הבא. בדקו את חלוקת הדרישות בקובץ. להלן דוגמאות מפורטות למבנה הדרישות והפורמט שעליכם לזהות:

Requirement 1: Inquiry Form Display

ממשק משתמש

הגדרת הצגת שדות הטופס וכותרת נימבוס במערכת.

When the system initializes, the web client SHALL display the inquiry form with input controls and render the Nimbus logo header image.
4

Requirement 4: Submission Confirmation

הודעת אישור

קבלת דף יחיד עם הודעת אישור ברורה לאחר הלחיצה על שליחה.

When the user submits the form, the application SHALL hide the form inputs and render a single confirmation message view.
6

Requirement 6: Accessibility Compliance

נגישות מובנית

אכיפת חוקת הנגישות הממשלתית הדיגיטלית (WCAG 2.1 AA).

The application user interface SHALL comply with WCAG 2.1 Level AA accessibility standards using correct ARIA properties on all form inputs.

שימו לב לניסוחים בפורמט **EARS-formatted requirements** שסוכן ה-AI מבין היטב, המבוססים על שימוש במילות מפתח קבועות כמו "When X happens, the system SHALL do Y" או "The X SHALL...".

שלב 8: יישום המערכת וג'נרוט קוד (Implementation Phase)

יצירת tasks.md וג'נרוט הקוד המלא על ידי ה-AI

שלב יישום וקוד

זהו שלב ייצור קוד המערכת על ידי ה-AI וסידור משימות הפיתוח. קובץ ה-tasks.md ייווצר וישמש כצ'קליסט לפיתוח. ה-AI יבצע את ג'נרוט קוד ה-Frontend (קובצי HTML/JS/CSS מקומיים הכוללים את חוקת העיצוב).

💬 עבודה אינטראקטיבית וניהול משימות מול הסוכן:

במהלך ייצור הקוד, יש לכם אפשרות מלאה לדבר ולשאול את הסוכן שאלות מכוונות, לקבל סטטוס ולהנחות אותו להמשך עבודה:

1. שאילתת סטטוס בשפה חופשית:

תוכלו להקליד ישירות בצ'אט את המשפט הבא:

show me what you are doing

בתגובה, הסוכן יציג בפניכם את כל השלבים שבוצעו עד כה ויבקש את אישורכם המפורש כדי להמשיך הלאה.

2. מעקב התקדמות בתוך קובץ tasks.md:

פתחו את קובץ המשימות שנוצר וצפו בהתקדמות המשימות שהוגדרו על ידי הסוכן. בקובץ תוכלו לזהות את שלבי ההתקדמות הבאים בזמן אמת:

task in progress task completed start task task queued

💡 שימו לב: עבור כל משימה מוגדרת בקובץ ה-Tasks, תוכלו לראות את המיפוי והקישור הישיר שלה לשלב ה-Requirements המקביל!

🔍 ביצוע Code Review קצר בצוות

  • ✦ ולידציות וקלט: חפשו את רכיבי ה-email או ה-phone number. האם אתם מזהים הוראות לסוכן לבצע בדיקות ולידציה על הקלטים הללו בדפדפן המקומי (JS Validation)?
  • ✦ שילוב לוגו נימבוס: ודאו שרכיב ה-Header של העמוד מפנה בצורה תקינה לקובץ התמונה images/header/nimbus_logo.png.
